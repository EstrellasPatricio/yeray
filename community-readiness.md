# Community Readiness

## Licencia escogida

GPL v3, para el equipo es importante que los proyectos derivados sigan teniendo un impacto en la comunidad y sean de código abierto. Queremos evitar que una corporación se aproveche del proyecto y obtenga un beneficio comercial

## Contenido mínimo del README

- Contexto del proyecto
- Stack tencológico
- Desarrollo y colaboración
- Estructura del proyecto
- Flujo de trabajo y convenciones
- Créditos
- Contacto

## Reporte de bugs

- Se debe crear un issue en el repo con el bug o funcionalidad
  - Si se trata de un bug se deberá empezar con `bug/`
  - Si se trata de una funcionalidad se deberá empezar con `feat/`
- Se debe incluir una descripción detallada de lo que busca corregir/implementar
- A partir de ahí, un admin validará/rechazará el issue y le asignará un desarrollador.

## PRs

La estructura de la PR puede ser utilizada por cualquier persona, sea miembro o no del equipo. No contiene menciones especiales ni requiere conocer el flujo del equipo ni convenciones.

## Code of Conduct

- Los títulos y descipciones de las PRs, Issues y Comentarios deben ser respetuosos: es decir, no deben contener comentarios ofensivos hacia ninguna comunidad.
- En el caso de encontrar contenido irrespetuoso, se dejarán de revisar y aceptar las PRs, comentarios o Issues que este usuario suba de ahí en adelante.
- De igual forma, el código no debe contener ningún tipo de contenido explicado previamente.

> [!important]
> En caso de inclumplir las normas más de 3 veces, serás reportado en Github.

## GOOD FIRST ISSUE

- Resolver dudas
- Bugs mínimos visuales en el frontend
- Análisis de librerías
- Limpieza de código en un Script
